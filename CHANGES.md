# Changelog: Automatic Caption Generator

Comparing `legacy/Automatic Caption Generator - old.html` (original version) to `Automatic Caption Generator v2.html` (current version).

The original tool was a single-shot pipeline: enter an API key, pick a file, click Generate, download an SRT. There was no way to fix a mistake short of editing the downloaded file by hand, and nothing about your session — not even the API key — survived a page reload. Since then it's been rebuilt into an editing and production tool: a full caption editor with undo and find/replace, a safety net so a crashed tab doesn't cost you your work, and a more reliable transcription pipeline underneath it all. What follows is what's actually changed.

## Audio processing & reliability

- **Choice of transcription provider.** OpenAI Whisper (the default) or ElevenLabs Scribe, picked right above the Generate button. Both are normalized to the same word-level timing shape internally, so nothing about caption generation, editing, or export depends on which one ran — only the transcription step itself changes.
- **Fast video audio extraction.** Previously, extracting audio from a video ran in real time (a 30-minute video took ~30 minutes just to extract audio, with a hardcoded timeout that could kill long files outright). Now it decodes and downsamples via the Web Audio API in seconds, with the old real-time method kept only as an automatic fallback if fast decoding fails.
- **Automatic chunking for large files.** Files that would exceed the selected provider's upload limit (25MB for Whisper; a generous cap well under ElevenLabs' 5GB limit, so typical multi-hour training audio needs few or no chunks) are now automatically split into chunks, transcribed separately, and stitched back together with correct timing offsets. Previously, long files would simply fail with a 413 error.
- **Retry logic for transient API failures.** Transcription requests now retry with backoff on 429/5xx errors and network failures (up to 3 attempts) instead of failing the entire file on a single transient error.
- **Fixed silent caption data loss.** Previously, if the caption-to-audio word matcher couldn't confidently place a segment, that text was silently dropped from the output with no trace. It's now placed using an approximate position and flagged on the caption card ("verify manually") instead of disappearing.
- **Fixed AI-segmented captions scrambling, especially toward the end of longer files.** The matcher that locates each AI-chosen caption's timing used to search fresh from scratch for every caption; if a single word failed to match (a mishearing, a number written differently, or — the specific bug found — a hyphenated compound word like "fit-content" tokenized two different ways by two different normalizers), it fell back to a *guessed* position instead of a real one. Every caption after that point then searched from an increasingly wrong starting position for the rest of the file, producing garbled, mismatched text. Segmentation now aligns the entire transcript to word timestamps once (`alignTranscriptToWords`), then walks the AI's chosen segments against that alignment in lockstep — a single bad word now only costs confidence on that one caption instead of derailing everything downstream of it.
- **Fixed missing punctuation in captions.** Whisper/ElevenLabs' word-level timestamps come back as bare text with no trailing punctuation, even though the polished full transcript has it — since captions are now built directly from word timing (see below), they were silently losing every period and comma, and sentence/clause-boundary detection (which depends on that punctuation) stopped working too. Punctuation is now restored from the full transcript onto each word before segmentation runs (`attachPunctuationToWords`).
- **Fixed a latent bug in the fallback segmenter** where a single sentence longer than the character limit had no further splitting logic and could ship as one oversized caption.
- **GPT segmentation truncation fix** — transcripts are now chunked before being sent for segmentation, so a long file can no longer produce a GPT response that gets cut off mid-JSON (`finish_reason: "length"`), which previously degraded the whole file to fallback splitting.

## Caption generation quality

- **Configurable caption settings** (max/target characters, min/max time on screen, max reading speed, gap-merge threshold, pause-break threshold, lead-in/hold padding), with a one-click reset to defaults — previously every one of these was a hardcoded constant (a flat 60-character hard cap baked into the GPT prompt, no duration or reading-speed limits at all).
- **Choice of segmentation method**, via a "Segmentation method" dropdown. Rule-based (the default) splits at sentence ends first, then commas/semicolons, then clause boundaries, with word boundaries only as a last resort — enforced by code, free, and instant. AI-assisted segmentation (asking a GPT model to do it instead) is also available for anyone who prefers a model's judgment call for the initial grouping, with the same rule-based limits applied underneath as a mechanical safety net if a GPT-chosen segment runs too long or spans a long pause.
- **Pause-aware breaking and a maximum time-on-screen cap.** Captions now also break on long silences between words, not just punctuation, and are capped at a configurable maximum duration (previously there was only ever a minimum, via a blanket "extend the last caption by 1 second" hack).
- **Lead-in/hold timing padding.** Captions are timed to the literal acoustic start/end of the matched words, which in practice reads as slightly late — viewers need a beat to start reading, and a caption vanishing the instant the last word ends feels abrupt. Captions now start a configurable amount earlier (default 0.1s) and end a configurable amount later (default 0.2s) than the raw word timestamps, standard practice in caption style guides. Applied in one left-to-right pass (`applyCaptionPadding`) that's provably overlap-safe — each caption's nudge is bounded by its neighbor's current (possibly already-padded) position, so it silently applies less than the configured amount, down to none, rather than ever overlapping.
- **Rule-based captions now aim for target length instead of packing to the maximum.** Previously, a long sentence was greedily chopped as large as possible, over and over, until whatever text was left at the very end of the sentence stood alone as a short, awkward "dangling" caption (e.g. a caption reading just `"settings."`). Segmentation now groups words into sentences/pause-bounded units first, and only when a unit is too long for one caption does it get divided — into pieces close to target length (not max), preferring to land the split on punctuation.
- **Editable AI prompt.** When an AI segmentation method is selected, the exact prompt sent to the model is editable in the settings panel — placeholders for the character limits and transcript fill in automatically — with a one-click reset back to the default wording.
- **Regenerate without re-transcribing.** A cached transcript (from whichever provider ran) lets you re-run just the segmentation/timing step after changing settings, without paying for transcription again. Switching the transcription provider afterward doesn't affect an already-transcribed file - Regenerate keeps using the cached result.

## Editing capabilities (the original had none)

The original SRT viewer was strictly read-only — the only way to fix a mistake was editing the downloaded file by hand. Everything below is new:

- **Auto-save** on every keystroke (no "Save Changes" button to remember to click).
- **Editable start/end timestamps** per caption, with flexible time parsing and overlap-safe validation against neighboring captions.
- **Merge / Split / Insert / Delete** actions on individual captions. Insert adds a blank caption immediately after the current one (duration defaults to the minimum-time-on-screen setting, capped against the next caption so it never overlaps) — for filling in a gap, e.g. text that got dropped during matching, rather than only being able to edit what generation already produced.
- **Undo** (button + Ctrl/Cmd+Z) covers merge, split, insert, delete, regenerate, timestamp edits, and plain text edits. Leaving a caption after changing its text pushes one undo step for the whole edit, not per keystroke.
- **Find & Replace**, reachable from the transcript editor header. Fixes a word or phrase consistently across every caption in the current file, or across every processed file at once (a checkbox toggles the scope), instead of requiring per-caption manual edits. Case-sensitivity is optional; each affected file gets its own undo snapshot pushed before it's modified, so undoing on that file reverts just its replacements.
- **Bounded single-caption preview**: clicking a caption plays only that caption's span and pauses automatically, rather than continuing playback indefinitely. The native play button still resumes normal full playback.
- **Scroll position preserved** across merge/split/insert/delete/undo/regenerate, instead of resetting to the top of a long caption list after every edit. Each file also now remembers its own scroll position when switching between file tabs, defaulting to the top for a file you haven't looked at yet.
- **Shift+↑/↓ jumps to the next/previous flagged caption**, skipping over clean ones — for reviewing just what needs attention (approximated text, uncertain matches, screen-time issues, etc.) in a long file instead of stepping through every caption in order.
- **"Fix Issues" button** (next to Undo) mechanically fixes what has an actual deterministic fix: extends captions that are too brief on screen or read too fast (capped at the next caption's start, so it can never introduce an overlap), and splits captions that are too long using the same sentence/clause/word-boundary priority the initial segmentation uses. Deliberately leaves approximated timing, uncertain word-match, text-divergence, and very-short-text flags alone - there's no algorithmic fix for "is this text actually correct," only a human listening to the audio can resolve those. One undo step for the whole pass.
- **Optional native spellcheck** on caption text (on by default), with a tooltip noting it'll also flag technical jargon (Beckhoff, TwinCAT, etc.) that isn't in the browser's dictionary.

## Quality & validation

- **Reading-speed (characters/second) and screen-time checks (both too brief and too long)**, in addition to the original length-only check (a single hardcoded 65-character bar with no other signal).
- **Per-caption match-confidence and "approximated" flags** surfaced directly on each caption card, not just in an aggregate summary with no way to tell which specific caption needed a look.
- **Text-divergence detection** now points to the specific caption where the generated text first diverges from the original transcript, instead of only reporting an aggregate character/word difference.

## Data safety & persistence (the original saved nothing — not even the API key)

- **Session recovery.** Caption/transcript work now periodically saves to the browser (IndexedDB) as you edit. If the tab crashes, gets closed, or reloads before you've downloaded your captions, reopening the page shows a banner offering to restore that work — re-add the same audio/video file(s) afterward and they'll pick up right where the restored captions left off, without re-transcribing. Only caption text and timing are saved, deliberately not the audio/video files themselves (you already have the originals, and persisting potentially large media blobs just for this would be a heavy, mostly redundant storage cost).
- **Generate only processes files that still need it.** Previously, clicking "Generate Professional Captions" wiped and re-transcribed *every* selected file from scratch, including ones you'd already generated and hand-edited — so adding one new file to a batch meant losing all your edits on the others. Generate now only transcribes files that don't already have finished captions — already-processed files, edits included, are left completely alone. A file that previously failed has no cached captions, so it's naturally retried on the next Generate. To force a full re-transcription of an already-processed file (e.g. after switching providers), remove it from the list and add it back — this also clears its cached transcript, quality data, and undo history.
- **Content-aware duplicate detection.** Adding a file with the same name as one already in the list was previously always treated as a duplicate and silently skipped, even if it was actually different content re-exported under the same filename — leaving stale captions attached to audio they no longer matched, with no indication anything was wrong. File size and last-modified date are now compared too: a true duplicate (same name, size, and date) is still skipped, but a same-named file with different size/date replaces the old entry in place and clears its cached transcript/captions/quality data, so it's picked up as needing (re)processing instead of silently keeping stale work. The same check covers re-adding a file after a session restore, where there's no live file object yet to compare against until the size/date recorded at save time is consulted.
- **Persistence** added for API keys (opt-in via checkbox, per provider), technical terms dictionary, caption settings, download format, save locations, theme, and spellcheck preference — the original persisted nothing between sessions, including the API key, which had to be re-typed on every page load.
- **Unsaved-work warning** before closing the tab if there's processed caption work that hasn't been downloaded.

## Export & troubleshooting

- **WebVTT export** added alongside SRT, via a format selector (persisted).
- Consolidated the old "Rebuild SRT" / "Save Changes" / "Download Current SRT" trio into fewer, clearer actions now that edits auto-save.
- **Custom save locations** (Chromium browsers only, via the File System Access API). Caption/transcript downloads and debug exports can each be pointed at their own folder instead of always going to the browser's default downloads location — picked once in Settings, remembered across reloads (scoped to this file's exact path), with an on-screen confirmation naming the folder each time a file actually lands there.
- **Debug info export.** A "🐛 Export Debug Info" button downloads a JSON snapshot of current settings, cached transcriptions (full text + word timestamps), generated captions, quality data, and the processing log — meant to be handed over directly for troubleshooting instead of describing an issue secondhand. Deliberately never includes API key values, only whether one is configured.

## Interface & visual design

- **Settings reorganized around how they're actually used.** Transcription provider and segmentation method — the two choices made before generating — sit inline, always visible, right above the Generate button. The more rarely-touched tuning settings (character/duration/reading-speed limits, gap/pause thresholds, the AI prompt editor) live in a collapsible section beneath them (collapsed by default), with a "Show Tuning Settings" shortcut next to Regenerate Captions that expands it and scrolls up to it. A separate ⚙️ Settings modal, reachable from the header, holds just API keys and save locations.
- **Full re-theme**: replaced the generic purple/blue gradient look with a Beckhoff-branded dark red / white / black palette, plus **dark mode** with a toggle switch (persisted, defaults to OS preference).
- **Custom-built audio player** (play/pause, seekbar, volume, time display, CSS-drawn icons) replacing the native `<audio controls>`, since native controls can't be reliably themed across browsers — plus **playback speed control** (0.5x–2x).
- **Sticky header**, so the Settings and What's New buttons stay reachable while scrolling through a long caption list.
- **Keyboard shortcuts**: Space (play/pause), Left/Right (seek ±5s), Up/Down (jump between captions), Shift+Up/Down (jump to next/previous flagged caption), Ctrl/Cmd+Z (undo) — none of these existed before.
- **Collapsible, reformatted info box.** The intro "Smart Caption Intelligence" explanation is now a scannable bullet list instead of a paragraph of prose, and can be collapsed once it's no longer needed (persisted).
- **Themed scrollbars** matching light/dark mode.

## Update notifications

- **Browser build**: a dismissible banner plus a "Check for updates on startup" toggle in Settings. Checks this repo's GitHub releases at most once a day and shows a banner with a link to the release if a newer version is found - never anything more invasive than that, and off entirely if the toggle is disabled. Previously there was no way to know a newer version existed short of happening to check GitHub yourself. Dismissing the banner only clears it for that day - it reappears at the next daily check for as long as that version is still the latest, rather than being suppressed permanently.
- **Electron build's Settings now shows the current version too** (in place of the toggle, which doesn't apply there - this build already updates itself automatically), instead of having no update-related information at all.
- **Electron build**: wired to the same GitHub releases via `electron-updater` instead - checks silently on launch, downloads a newer version in the background if one exists, and shows a native "Restart & Install" / "Later" dialog once it's ready. No visible Settings toggle for this build (redundant next to the native flow); nothing to see at all until an update is actually available. Requires releases to be published with `electron-builder --publish always` (not a manual upload of just the installer) so the metadata the updater reads actually exists.

## Application icon

- **Custom app icon** (previously the default Electron icon) - now used for the window, taskbar, and installer, and inlined as the browser tab's favicon for the plain HTML build too. Generated from the app's logo with the outer corners of the source image made transparent, so it renders as a proper rounded-square icon rather than a red rounded square sitting inside a visibly white tile.

## Not changed

- Still a single self-contained HTML file with no build step or server — open it directly in a browser.
- High-level pipeline is unchanged: transcription → caption segmentation → SRT/VTT export. Rule-based segmentation now builds captions directly from word timestamps in one pass (sentence/pause/duration-aware) instead of splitting text first and fuzzy-matching it to timing afterward; AI segmentation still does its first-pass grouping on text, then runs the same word-timing rules over each resulting segment as a safety net before finalizing. Both apply identically regardless of which transcription provider produced the words.
