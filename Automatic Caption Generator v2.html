🆕 What's New

The original tool was a single-shot pipeline: enter an API key, pick a file, click Generate, download an SRT. There was no way to fix a mistake short of editing the downloaded file by hand, and nothing about your session - not even the API key - survived a page reload. Since then it's been rebuilt into an editing and production tool: a full caption editor with undo and find/replace, a safety net so a crashed tab doesn't cost you your work, and a more reliable transcription pipeline underneath it all. The sections below cover what's actually changed.

Audio processing & reliability

  • Choice of transcription provider. OpenAI Whisper (the default) or ElevenLabs Scribe, picked right above the Generate button. Both return the same word-level timing under the hood, so switching providers doesn't change how captions are generated afterward - just how the audio gets turned into text in the first place.
  • Fast video audio extraction. Previously ran in real time (a 30-minute video took ~30 minutes just to extract audio, with a hardcoded timeout that could kill long files outright). Now decodes and downsamples via the Web Audio API in seconds, with the old real-time method kept only as an automatic fallback.
  • Automatic chunking for large files. Previously a file over Whisper's 25MB upload limit simply failed. Oversized files are now split into chunks automatically, transcribed separately, and stitched back together with corrected timestamps - transparent for both providers.
  • Retry logic for transient transcription failures (429/5xx and network errors), up to 3 attempts with backoff, instead of failing the whole file on one bad response.
  • Fixed silent caption data loss. Previously, if the word-matcher couldn't confidently place a caption segment, that text was dropped with no trace at all. It's now placed at an approximate position and flagged for manual review instead of disappearing.
  • Fixed AI-segmented captions scrambling, especially toward the end of longer files. The old matcher searched fresh for each caption's timing and, if even one word failed to match (e.g. a hyphenated term tokenized two different ways), permanently lost its place - every caption after that point kept searching from the wrong position for the rest of the file. Segmentation now aligns the whole transcript to word timestamps once, then walks the AI's chosen segments against that alignment in lockstep, so a single mismatch only affects the one caption instead of cascading.
  • Fixed missing punctuation in captions. Whisper/ElevenLabs' word-level timestamps come back without punctuation attached, even though the full transcript has it - so captions built from word timing were silently losing every period and comma. Punctuation is now restored from the full transcript before segmentation runs.
  • GPT segmentation truncation fix - transcripts are chunked before being sent for segmentation, so a long file can no longer produce a GPT response that gets cut off mid-JSON.
  • Fixed hyphenated compounds (non-TwinSAFE, I-O) producing duplicated or orphaned single-word captions - restoring punctuation onto Whisper's bare words could let one word's fuzzy match swallow an entire hyphenated transcript token, stranding the next word with no match at all.

Caption generation quality

  • Configurable caption settings (max/target characters, min/max time on screen, max reading speed, gap-merge threshold, pause-break threshold, lead-in/hold padding), with a reset-to-defaults button - previously every one of these was a hardcoded constant. Default maximum time on screen is 5 seconds (previously 7).
  • Export/import the dictionary and caption settings as a single JSON file, via buttons next to Reset to defaults - for backing up a tuned configuration or handing a colleague the exact same setup. Never includes API keys or other personal preferences.
  • Choice of segmentation method. Rule-based (the default) splits at sentence ends first, then commas/semicolons, then clause boundaries, with word boundaries only as a last resort - guaranteed by code, free, and instant. AI-assisted segmentation is still available for anyone who prefers a model's judgment call, with the same rule-based limits applied underneath as a mechanical safety net.
  • Pause-aware breaking and a maximum time-on-screen cap - captions now also break on long silences between words, not just punctuation, and are capped at a configurable maximum duration rather than only ever having a minimum.
  • Lead-in/hold timing padding. Captions now start slightly before and end slightly after the literal spoken word (defaults: 0.1s early, 0.2s held) - standard captioning practice, since syncing exactly to speech onset/offset reads as slightly late. Provably never overlaps a neighboring caption.
  • Rule-based captions now aim for target length instead of packing every caption to the maximum. Previously, a long sentence was chopped as large as possible over and over, leaving whatever was left at the very end standing alone as a short, awkward "dangling" caption.
  • Fixed abbreviations and URLs fragmenting into one-letter captions (e.g. "Safe I." / "O." / "can be dispersed..." from I/O read aloud, or www. / example. / com. from a spoken URL) - a trailing period is no longer always treated as a sentence end.
  • Fixed captions that were too long in on-screen time but not in character count never getting split. Piece count for an over-long sentence now factors in duration as well as length, and two steps that run after that splitting decision - closing small gaps between captions, and lead-in/hold padding - are both capped at the maximum duration too, so they can no longer push an already-correct caption back over the limit.
  • Editable, resettable AI prompt for anyone using AI segmentation, with placeholders for the character limits and transcript that fill in automatically.
  • Regenerate without re-transcribing - re-run segmentation/timing after changing settings without paying for transcription again.

Editing capabilities (the original had none)

The original SRT viewer was read-only start to finish - fixing a mistake meant editing the downloaded file by hand. Every item below is new:

  • Auto-save on every keystroke - no "Save Changes" button.
  • Editable start/end timestamps per caption, with overlap-safe validation against neighboring captions.
  • Merge / Split / Insert / Delete actions on individual captions - Insert adds a blank caption right after the current one, for filling a gap rather than only editing what generation already produced.
  • Undo (button + Ctrl/Cmd+Z) covers merge, split, insert, delete, regenerate, timestamp edits, and plain text edits.
  • Find & Replace - fix a word or phrase consistently across every caption, either in just the current file or across every processed file at once, instead of editing each caption by hand. Each affected file gets its own undo step.
  • Bounded single-caption preview - clicking a caption plays only that caption's span, then pauses.
  • Scroll position preserved across every edit, instead of jumping back to the top of a long caption list each time - and each file remembers its own scroll position when switching between tabs.
  • Shift+↑/↓ jumps to the next flagged caption, skipping clean ones, for reviewing just what needs attention in a long file.
  • "Fix Issues" button (next to Undo) merges a too-brief or too-fast caption into an adjacent one when it looks like a fragment of the same clause and the combined result fits within limits, otherwise extends it instead; and splits captions that are too long - whether in characters or in on-screen time - all in one undoable step. Leaves approximated/uncertain-match/text-divergence flags alone, since those need a human to actually listen and verify, not a mechanical fix.
  • Optional native spellcheck on caption text (on by default), aware that it'll flag technical jargon not in the browser's dictionary.

Quality & validation

  • Reading-speed and screen-time checks (both too brief and too long), in addition to length - previously length was the only thing checked, against a single hardcoded 65-character bar.
  • Per-caption match-confidence and "approximated" flags shown directly on each caption card, instead of an aggregate pass/fail with no way to tell which caption actually needs a look.
  • Text-divergence detection points to the specific caption where generated text first diverges from the original transcript, rather than only reporting an aggregate character/word difference.

Data safety & persistence (the original saved nothing - not even the API key)

  • Session recovery. Caption/transcript work is now periodically saved in the browser (IndexedDB) as you edit. If the tab crashes, gets closed, or reloads before you've downloaded your captions, reopening the page offers to restore that work - re-add the same audio/video file(s) afterward and they'll pick up right where the restored captions left off, without re-transcribing. Only the caption text and timing are saved, not the audio/video files themselves.
  • Generate only processes files that need it. Previously, clicking Generate wiped and re-transcribed every selected file from scratch every time, so adding one new file to a batch destroyed all edits on the others. Generate now only transcribes files that don't already have finished captions - everything else, edits included, is left completely alone. (To force a full re-transcription of an already-processed file, remove it from the list and add it back.)
  • Content-aware duplicate detection. Adding a file with the same name as one already in the list used to always be treated as a duplicate and silently skipped, even if it was actually different, re-exported content. File size and modified date are now compared too - a genuine duplicate is still skipped, but a same-named file with different content replaces the old entry and clears its stale captions instead of silently keeping them. The same check covers re-adding a file after a session restore.
  • Persistent settings. API keys (opt-in), the technical terms dictionary, caption settings, download format, save locations, theme, and spellcheck preference all now survive a reload - previously every one of these reset to defaults (or, for the API key, to blank) on every page load.
  • Unsaved-work warning before closing the tab if there's processed caption work that hasn't been downloaded.

Export & troubleshooting

  • WebVTT export added alongside SRT, via a persisted format selector.
  • Custom save locations (Chromium browsers only) - pick separate folders for caption/transcript downloads and debug exports instead of always using the browser's default downloads folder. Remembered across reloads, with an on-screen confirmation of exactly where each file saved.
  • Debug info export - downloads a JSON snapshot of current settings, cached transcriptions, generated captions, quality data, and the processing log, for handing over when something looks wrong. Never includes API key values, only whether one is set.

Interface & visual design

  • Settings reorganized for how they're actually used. Transcription provider and segmentation method - the two choices you make before generating - sit right above the Generate button, always visible. The more rarely-touched tuning settings live in a collapsible section beneath them, with a "Show Tuning Settings" shortcut next to Regenerate. A separate ⚙️ Settings panel holds API keys and save locations, out of the way of the main workflow.
  • Full re-theme to a Beckhoff-branded dark red / white / black palette, with a dark mode toggle (persisted, defaults to OS preference), replacing the original's generic purple/blue gradient.
  • Custom-built, themed audio player (play/pause, seekbar, volume, time display, CSS-drawn icons) replacing the native, unthemeable browser controls, plus a playback speed control (0.5x-2x).
  • Sticky header - stays pinned to the top of the page while scrolling, so Settings and What's New are always reachable.
  • Keyboard shortcuts: Space (play/pause), Left/Right (seek), Up/Down (jump between captions), Shift+Up/Down (jump to next/previous flagged caption), Ctrl/Cmd+Z (undo) - none of these existed before.
  • Collapsible, reformatted info box - the intro explanation is now a scannable bullet list instead of a wall of text, and can be collapsed once you don't need it.
  • Toast notifications now fade in and out instead of abruptly appearing and disappearing.
  • Unified the left-accented boxes' styling (Technical Terms Dictionary, How It Works, Caption Generation Settings, Settings modal sections) - all now share the same rounded corners and colored accent border.
  • Themed scrollbars matching light/dark mode.

Update notifications

  • Browser build: a dismissible banner plus a "Check for updates on startup" toggle in Settings. Checks this repo's GitHub releases at most once a day and shows a banner with a link if a newer version exists - nothing more invasive than that, and off entirely if the toggle is disabled. Dismissing only clears it for the day - it comes back at the next daily check for as long as that version is still current.
  • Electron build: checks the same releases silently on launch and, if a newer version is available, downloads it in the background and shows a native "Restart & Install" / "Later" dialog once it's ready. No separate toggle for this build - there's nothing to configure - but Settings now shows the current version number in its place.

Application icon

  • Custom app icon, replacing the default Electron icon - used for the window, taskbar, and installer, and inlined as the browser tab's favicon for the plain HTML build too. The outer corners of the source artwork are transparent, so it reads as a proper rounded-square icon instead of a red rounded square sitting inside a visibly white tile.
